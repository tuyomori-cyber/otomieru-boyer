# テーマ

音声再生中の再生線を、スナップショット間の補間によって滑らかに追従させる

# 目的

再生位置の更新間隔によるカクつきを抑え、音声再生中の再生線を連続的かつ自然に表示する。

# 前提認識

- 音声スナップショット間をUI側で補間し、再生線を最大約60 FPSで連続表示できている
- シーク・停止・巻き戻り時は即時同期し、その後の補間進行もテストで確認済み
- 最大縮小時のカクつきは低速移動のピクセル表現だけではなく、実測でUI描画が約11 FPS / 138 msまで低下することが主因と判明した
- 再生線を隣接2 px列へ輝度分配して描画する方式を実装し、縮小時のピクセル境界での跳ねを軽減した
- 小数px位置の輝度分配はユニットテストで確認済み
- メインの再生線と下部バーの再生線の両方に輝度分配を適用済み
- UI FPS / frame time / pixels_per_point の診断表示を追加し、実フレーム間隔を確認可能にした
- 高倍率では約60 FPSを維持できる一方、縮小時はカクつくことを実機で確認した
- 現在は表示範囲内のSTFTフレームとピッチを毎フレーム走査し、強度のあるセルごとに矩形を描画しているため、縮小時は表示する時間範囲が広がるほど描画矩形数が増加する
- スペクトログラム描画が60 FPSの再描画要求に追いつかなくなることで、補間済みの再生線も実際には十分なフレームレートで描画できず、カクついて見える
- 縮小時の描画負荷を抑えるため、時間方向の描画ダウンサンプリングを行い、画面上の1 pxあたりに対応する複数の時間フレームを集約して描画する方針とする

# MVP ゴール

- 再生中の再生線がスナップショット更新間隔に依存せず、滑らかに連続表示される
- シーク・停止・巻き戻り時に再生線が即時に正しい位置へ同期する
- 現状の60 FPS補間表示で基本的な滑らかさを確保する
- 縮小時にスペクトログラムの描画量が過剰に増えないようにし、実測で約60 FPSを維持できる状態を確保する

# 非ゴール

- 現時点で120 FPS以上の描画を必須としない
- ディスプレイのリフレッシュレートを超えて描画することを目的としない
- 再生線の滑らかさのためだけに、CPU/GPU負荷を大幅に増加させない
- 最大縮小時のカクつきをFPS向上だけで解決しようとしない
