## テーマ

- `仕様書.md` を実装可能な段階計画へ落とし込み、耳コピ向け Linux ネイティブ MVP を Rust で組み上げる
- 音響解析ツール化を避けつつ、「開く・聴く・遅くする・繰り返す・見る・クリックして確かめる」を最短で成立させる

## 目的

- MVP 完成条件に直結する機能を、仕様書の推奨開発順序に沿って順番に実装できる状態を維持する
- 再生系、解析系、描画系の責務を分離し、再生位置とスペクトログラムが常に同期する基盤を作る

## 前提認識

- 対象アプリは Linux ネイティブの耳コピ支援プレイヤーであり、総合音響解析ソフトは目指さない
- ダウンロード、MuseScore 直接連携、自動採譜、AI 解析、詳細 FFT 調整は MVP 外
- 速度変更より先に、通常再生・スペクトログラム表示・同期スクロールを完成させる
- スペクトログラムは事前計算方式とし、再生中に FFT を回し続けない
- スペクトログラムの時間軸は元音源基準で保持し、速度変更時も解析データは再生成しない
- UI には解析パラメータを出さず、ユーザーには音階ベースの見え方だけを提示する
- リポジトリは既存実装なしで、`仕様書.md` のみがある新規着手状態であることを確認済み
- 実装は既存コードの差分修正ではなく、初期セットアップから開始する
- 初期セットアップ後は `eframe/egui` の最小アプリを起点に、仕様書準拠の `src/` 骨格を作成する
- Rust プロジェクトの初期セットアップと `eframe/egui` の最小ウィンドウ起動まで完了している
- `app` / `audio` / `analysis` / `ui` / `model` の仕様書準拠の骨格まで作成済みである
- `cargo check` と `cargo fmt` により初期構成の成立を確認済み
- `Symphonia` を依存追加し、音声ファイルを PCM `f32` のインターリーブ配列へデコードする `audio::decoder::decode_file(...)` を実装済み
- `DecodedAudio` から `Track` を生成する変換を追加済みで、`duration_seconds()` も `DecodedAudio` 側で計算できる
- `Symphonia` は WAV / MP3 / FLAC / OGG / AAC / MP4 系を扱える前提で導入している
- `cargo check` によりデコーダ導入後のビルド成立を確認済み
- ファイルダイアログを導入し、`Open` から `Symphonia` デコード、`Track` 生成、`AppState` 更新まで接続済み
- 読み込み済みファイル情報と状態メッセージを UI に反映済み
- `CPAL` を使う通常再生エンジンの最小実装を追加済みで、`audio::player` に `Track` のロードと Play / Pause / Stop を実装済み
- `Play` / `Stop` を `audio::player` 経由の実音声出力へ接続済み
- Linux の `CPAL` が利用する ALSA バックエンドのシステム依存について、`pkg-config` / ALSA 依存を導入済み
- `cargo check` が成功し、通常再生基盤を含む現状コードのビルドが成立している
- `Space` キーで再生 / ポーズを切り替えられる操作を追加済み
- `Play` 横に先頭へ戻る `|<` ボタンを追加済み。停止ではなく頭出しとして動作し、再生中は曲頭から再開、ポーズ中や停止中は位置だけ先頭へ戻す
- 直近の UI 操作追加後も `cargo check` が成功している
- 次段は仕様書順に STFT の事前計算と静止スペクトログラム実装へ進む

## MVP 完成条件

- MP3 などの音声ファイルを開ける
- 再生、一時停止、停止、シーク、再生位置表示ができる
- スペクトログラムがピアノ鍵盤と縦軸同期して表示される
- 再生位置カーソルと表示スクロールが同期する
- スペクトログラム上のドラッグで範囲選択できる
- 選択範囲をループ再生できる
- スペクトログラム上のクリックで対応音程の基準音を鳴らせる
- `0.50x` または `0.75x` でもピッチを維持した再生ができる

## 非ゴール

- YouTube ダウンロード機能の統合
- MuseScore の直接操作や MIDI 送信
- 自動採譜、コード認識、BPM 解析、楽器分離、ボーカル除去
- 波形編集、音声編集、DAW 機能、VST、プラグインシステム
- 複数トラック対応や詳細解析設定の露出

## 推奨内部構成

- `app/`: アプリ状態と全体統合
- `audio/decoder.rs`: 音声ファイル読み込みと PCM 化
- `audio/player.rs`: 再生、一時停止、停止、シーク、現在位置、ループ境界処理
- `audio/timestretch.rs`: ピッチ維持速度変更の境界
- `audio/preview_tone.rs`: クリック音程確認用の基準音再生
- `analysis/stft.rs`: Windowing、FFT、Magnitude 計算
- `analysis/spectrum.rs`: 表示用スペクトログラムデータ構造
- `analysis/pitch_map.rs`: `frequency ↔ MIDI` と `screen Y ↔ pitch`
- `ui/spectrogram.rs`: 中心描画、再生位置、クリック、ドラッグ選択、スクロール
- `ui/piano.rs`: 鍵盤描画と縦軸同期
- `ui/toolbar.rs`: Open、Play/Pause、Speed、Time、Loop
- `model/`: `Track`、`PlaybackState`、`Selection` のような中核データ

## 設計上の注意

- `audio::player` は UI を知らず、元音源時間ベースの `position` 管理に集中させる
- UI 側は再生状態を個別保持せず、中核 state を参照して描画と入力反映だけを行う
- 音声コールバック内で重い処理をしない
- 解析中に GUI を固めない
- 速度変更時は position の進み方だけを変え、スペクトログラム座標は変えない
- クリック音確認は初期実装では正弦波でよい
