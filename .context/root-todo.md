# Auto ToDo Root

## テーマ

- `otomieru-boyer` の音程維持付き速度変更と独立オクターブシフトを、実用的なストリーミング再生として安定化する。
- イコライザ機能を追加し、再生音の帯域強調・減衰をスペクトラム表示にも反映する。

## 目的

- 音程を維持した速度変更と独立したオクターブシフトを、安定したストリーミング再生として実用化する。
- スペクトラム表示とピアノロールを、時間軸・音高方向のズーム操作に対応させる。
- イコライザで強調・減衰した帯域を再生音とスペクトラム表示の両方へ反映する。

## 前提認識

- `AudioPlayer → DspEngine → Streaming worker → 固定長SPSCリング → CPAL callback`。
- worker は Rubber Band 3.3 のリアルタイム R2 engine で処理する。
- callback はリングから読むだけで、メモリ確保・Mutex・DSP計算を行わない。
- 速度比は `time_ratio = 1 / speed`、ピッチは `pitch_scale = 2^(semitones / 12)` として独立に設定する。
- Seek / Stop / LoopJump は generation を更新し、旧世代データを破棄する。
- スペクトラム表示は時間軸ズームに対応し、ポインタ位置の時間を中心に拡大／縮小する。
- Ctrl＋ホイールによる音高方向のズームでは、スペクトラムと左のピアノロールが同じ音高範囲を表示する。
- 音高方向のズームはポインタ位置の音高を中心に行い、ウィンドウの縦幅を超えない。
- 現在の縦ズームでは、表示領域の高さを固定したまま1音あたりを大きく描くため、拡大すると見える音高範囲が狭くなる。
- スペクトラムとピアノロールは可変の音高範囲を描ける構造になっており、表示範囲の選択を追加する場合は解析データの再生成を必要としない。
- 現在の解析対象の音高範囲を超えて解析対象自体を広げる場合は、音域幅に応じて解析時のCPU・メモリへの影響が増える。
- スペクトラムとピアノロールの表示領域は、タイムラインやステータス表示を除いた残りの縦高さへ追従するよう変更済みで、ウィンドウを縦に広げると両方の表示領域も縦に広がる。
- 縦方向の表示領域を広げることで、音高方向ズーム時の視認性を改善できる。
- 現状のスペクトラムは音源読み込み時に解析して保持した元音源のデータであり、再生時のDSPとは別経路になっている。
- イコライザを追加する場合、再生音はworker内でEQ処理し、スペクトラム表示は同じEQカーブを各音高帯域の色強度へ反映する方針が考えられる。
- EQによるスペクトラム表示の反映は、保持済みの解析データを利用すれば再解析なしでUI操作へ追従できる。

## MVP ゴール

- 音程維持付き速度変更と独立オクターブシフトを、実用的なストリーミング再生として安定して利用できる。
- スペクトラムとピアノロールで、時間軸および音高方向のズームを操作できる。
- 音高方向のズーム時にも、必要な音域を確認しやすい表示範囲を選択できる。
- ウィンドウの縦サイズに応じてスペクトラムとピアノロールの表示領域を広げ、縦ズーム時の視認性を改善する。
- イコライザで再生音の帯域を強調・減衰でき、スペクトラム表示にもその変化を反映できる。

## 非ゴール

- Linux以外の配布方法の整備は現時点では対象外。
- 解析対象そのものの音域を無制限に広げることは現時点では対象外。
