# テーマ

音声再生中の再生線を、表示倍率にかかわらず滑らかに追従させる。

# 目的

音声スナップショットの更新間隔によるカクつきを抑え、再生線を連続的に表示する。再生線更新のためにスペクトログラム本体を毎フレーム再構築しない。

# 現在の状態

- Done: 音声スナップショット間の再生位置をUI側で補間し、最大約60 FPSで再生線を更新する。
- Done: シーク、停止、巻き戻り時の即時同期と補間進行をテストで確認する。
- Done: 再生線を隣接する物理2 px列へ輝度分配して描画し、縮小時のピクセル境界での跳ねを軽減する。
- Done: UI FPS、フレーム時間、表示スケールの診断表示を追加する。
- Done: 表示幅の物理ピクセル数に合わせて時間フレームを最大強度で集約する。
- Done: スペクトログラム本体をテクスチャへキャッシュし、再生中はキャッシュ画像と再生線・ガイド類だけを描画する。
- Done: 表示範囲、表示サイズ、音程範囲、表示ゲイン、基音強調、音階の強調・減衰、EQ、音源の切替時にキャッシュを再生成する。
- Done: 先頭へ戻す操作で、再生位置と表示範囲をともに0秒へ戻す。
- Done: 新しい実機では全ズーム倍率で再生線が滑らかに追従することを確認した。

# MVP ゴール

- Done: 再生中の再生線がスナップショット更新間隔に依存せず、滑らかに連続表示される。
- Done: シーク、停止、巻き戻り時に再生線と表示範囲が即時に正しい位置へ同期する。
- Done: 縮小時もスペクトログラムの描画量を表示幅に応じて制限し、再生線の更新を妨げない。

# 残作業

1. 旧実機と新実機で、同じ音源・表示倍率・ウィンドウサイズのUI FPSを比較する。
2. 実音源で高倍率ズーム時とループ境界を含め、再生線の追従を確認する。
3. 高リフレッシュレート環境で、60 FPSを超える更新が必要か確認する。
4. 必要性が確認できた場合のみ、60 / 120 FPSまたはディスプレイ追従の更新方式と負荷を検討する。

# 非ゴール

- 実測上の必要性を確認せずに120 FPS以上の描画を実装しない。
- 再生線の滑らかさだけを理由に、スペクトログラムの毎フレーム再構築へ戻さない。

# 次の一手
