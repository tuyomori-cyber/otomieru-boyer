# v0.6.0 テスト項目

## 目的

v0.6.0の解析キャッシュにより、同一音源を再読込した際にSTFT・スペクトログラム解析を再利用できること、キャッシュ異常時も安全に通常解析へ戻れることを確認する。

- `[OK]`: 確認済み・問題なし
- `[ ]`: 未確認
- `[NG]`: 確認済み・問題あり
- 実機確認時は、OS、音源形式、音源の長さ、および初回・再読込のおおよその所要時間を各項目末尾へ記録する。

## 2. キャッシュ作成・再利用

- [OK] `CAC-01` キャッシュがない音源を開くと、音源と同じフォルダに`<音源ファイル名>.otomieru.spectrum.bin`が作成される。例: `song.flac`では`song.flac.otomieru.spectrum.bin`。
- [OK] `CAC-02` 初回読込後に同じ音源を再度開くと、ステータス表示に`解析キャッシュを利用しました。`が含まれる。
- [OK] `CAC-03` キャッシュ利用時も、再生、スペクトログラム、ピアノロール、シーク、Loop、音高メモが通常どおり利用できる。
- [OK] `CAC-04` 同一音源の再読込は、初回読込より解析待ちが短くなる。音源のデコード時間は残るため、完全な即時読込ではない。実機確認: キャッシュなし約18秒、キャッシュあり約8秒。
- [OK] `CAC-05` `ファイル → 保存`または`Ctrl+S`を実行しても、キャッシュとプロジェクトsidecar JSONが別ファイルとして維持される。
- [OK] `CAC-06` 音源の読込完了後、ステータス表示に合計の`読み込み時間: <秒>秒`が小数第2位まで表示される。キャッシュ利用時・通常解析時の双方で確認する。実機確認: キャッシュなし約18秒、キャッシュあり約8秒。

## 3. 無効化・復旧

- [OK] `INV-01` キャッシュファイルを削除してから音源を開くと、通常解析後にキャッシュを作成し直す。
- [OK] `INV-02` 音源ファイルを差し替えるか更新日時・サイズを変更してから開くと、古いキャッシュを使用せず、`解析キャッシュを再生成しました。`を含むステータスになる。
- [OK] `INV-03` キャッシュファイルの内容を破損させても、音源読込は失敗せず、通常解析とキャッシュ再保存へ進む。
- [OK] `INV-04` キャッシュがない音源を用意し、音源フォルダの書込権限だけを外してから開く。キャッシュ作成が失敗しても、再生・表示・既存sidecarの読込は継続し、ステータスにキャッシュ保存失敗が表示される。確認後はフォルダの書込権限を復元する。
